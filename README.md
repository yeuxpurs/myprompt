# myprompt · GPT-6 시대의 프롬프트 작업 공간

[사이트 열기](https://yeuxpurs.github.io/myprompt/)

기존의 분리된 도구 모음을 라이브러리, 스튜디오, 워크플로, 가이드로 다시 구성했습니다. 일본어 → 중국어 → 영어 → 베트남어 → 프랑스어 → 스페인어 → 한국어 순서로 언어를 선택하며, 기본 언어는 일본어입니다. 화면 문구뿐 아니라 기본 프롬프트 내용도 7개 언어로 제공합니다.

## 할 수 있는 일

- **라이브러리:** 글쓰기·리서치·업무·코딩·엔지니어링·창작 템플릿을 검색하고, 변수를 채워 복사합니다. 사용자 프롬프트 추가·편집·삭제, 즐겨찾기와 JSON 백업을 지원합니다.
- **유연한 편집:** 카드의 연필 버튼에서 제목·설명·본문·카테고리·태그를 수정합니다. 카테고리는 직접 입력할 수 있습니다. 태그는 Enter/쉼표로 추가하고, 클릭해서 이름을 바꾸며 ×로 삭제합니다. 목록의 태그를 눌러 필터링할 수 있고, 기본 템플릿을 수정하면 개인 사본으로 저장합니다.
- **스튜디오:** 목표, 맥락, 자료, 출력 조건을 정리해 프롬프트를 만듭니다. 기존 프롬프트 첨삭 기능은 이곳에 통합했습니다. 브라우저에서 구성과 빠진 조건을 점검하며, 외부 AI 추론을 실행하는 기능은 아닙니다.
- **워크플로·가이드:** 자료의 근거, 검증 방법, 도구 사용 범위, 완료 조건을 명확히 하는 작업 방식을 안내합니다.

‘GPT-6’는 템플릿과 작업 방식의 기준을 뜻합니다. 이 사이트에 GPT-6 모델이나 AI 실행 서버가 포함되는 것은 아닙니다. 완성한 프롬프트를 사용 중인 AI 서비스에 복사해 실행하세요. 특정 서비스나 Azure 배포에서 특정 모델을 사용할 수 있다고 보장하지 않습니다.

기존 **AI 자동 품질검사 에이전트는 제거**했습니다. 이미지와 요구사항을 함께 검토할 수 있는 시각 자료 검토 프롬프트는 유지합니다. 사이트가 이미지를 분석하거나 합격·불합격을 자동 판정하지 않습니다. 예전 도구 URL은 관련 새 화면으로 연결됩니다.

## 저장과 백업

프롬프트와 즐겨찾기, 언어 선택은 현재 브라우저의 `localStorage`에 저장합니다. 계정, 클라우드 저장, 기기 간 동기화, AI API 호출은 없습니다. 브라우저나 접속 주소가 달라지면 저장 공간도 달라집니다. 브라우저 데이터 삭제 전에는 **내보내기**로 JSON 파일을 보관하세요.

- 새 데이터는 `myprompt.v2`에 저장합니다.
- 기존 `promptUIData`와 `promptFavorites`가 있으면 처음 실행할 때 이전합니다. 원본 키는 지우지 않습니다.
- 새 JSON 백업과 기존 `{cats:…}`, `{data:{cats:…}}`, `{promptUIData:{cats:…}}` 백업을 가져올 수 있습니다.
- 가져오기는 기존 항목을 유지하면서 병합합니다. 내용이 같은 항목은 중복 추가하지 않고, 내용이 바뀐 버전은 별도 항목으로 남깁니다.
- 저장이 차단되거나 용량을 초과하면 상태를 화면에 알립니다. 해당 세션에서 편집한 내용은 메모리에 남으므로 내보내기로 보관할 수 있습니다.
- 손상된 새 저장 데이터는 자동으로 덮어쓰지 않습니다. 이후 저장할 때 `myprompt.v2.recovery.*`에 원본을 먼저 보관합니다.

처음 온라인으로 방문한 뒤에는 서비스 워커가 앱 파일을 캐시해 오프라인 사용을 지원합니다. 저장된 프롬프트의 백업은 이 캐시와 별개입니다.

## 실행

빌드나 패키지 설치가 필요 없는 정적 사이트입니다. Node.js 20 이상 또는 Python 3이 있으면 로컬 서버로 실행할 수 있습니다.

```sh
# macOS / Linux
./start-local.sh

# Node.js 직접 실행
node server/serve.mjs
# 다른 포트
node server/serve.mjs --port 8000
```

Windows에서는 `start-local.bat` 또는 `start-local.ps1`을 실행하세요. 기본 주소는 `http://127.0.0.1:8787/`입니다. 실행기는 Node.js가 없으면 Python 정적 서버로 전환합니다. Node 서버는 로컬 컴퓨터에만 연결을 허용하며 파일만 제공합니다.

`index.html`을 직접 열어도 기본 기능을 사용할 수 있습니다. `file://`에서는 서비스 워커가 등록되지 않고 브라우저에 따라 저장·클립보드 기능이 제한될 수 있으므로 로컬 서버 실행을 권장합니다.

GitHub Pages에서는 저장소 루트의 파일을 그대로 배포하면 됩니다. GitHub 저장소 **Settings → Pages**에서 배포할 브랜치와 `/(root)`를 선택합니다. 모든 앱 경로는 상대 경로이므로 `/myprompt/` 하위 주소에서도 작동합니다. API 키나 서버 환경 설정은 필요하지 않습니다.

## 검증

```sh
npm test
# 선택: Python으로 정적 경로를 한 번 더 확인
python3 tools/check-static.py
```

테스트는 데이터 이전·병합·변수·저장 오류, JavaScript 문법, 번역 키와 프롬프트 카탈로그, 내부 링크·이전 URL·오프라인 캐시 파일을 검사합니다. 의존 패키지를 다운로드하지 않습니다. 실제 화면 조작과 반응형 레이아웃은 브라우저에서 별도로 확인합니다.

주요 파일은 `assets/app.js`와 `assets/app.css`(화면), `assets/core.js`(데이터), `assets/i18n.js`(번역), `assets/prompts.js`(기본 프롬프트), `server/serve.mjs`(선택적 로컬 서버)입니다.
